# L2 数据说明：原始数据 → 逐笔流 → 订单簿

> 一句话：这个项目把数据走三站。**原始数据**（交易所给的委托、成交、快照）→ **逐笔流**（我们拼成的一张十列表，深沪长得一样）→ **订单簿**（沿逐笔流回放出来的盘口，和快照对账）。本文按这三站各讲一部分。

代码在 `lob_rebuild/src/lob/`：

| 文件 | 负责哪一站 |
| --- | --- |
| `sz_stock_build_orderbook.py` | 深交所：原始数据 → 逐笔流 |
| `sh_stock_build_orderbook.py` | 上交所：原始数据 → 逐笔流 |
| `build_orderbook.py` | 深沪共用：逐笔流 → 订单簿，以及和快照对账 |

演示：`lob_rebuild/notebooks/订单簿重建演示.ipynb`。教程：`SZ_订单簿重建教程.html`、`SH_订单簿重建教程.html`。

## 1.3 通用约定（所有文件都一样）

| 项目 | 约定 |

| 列名 | 含义 | 深交所 | 上交所 |
| --- | --- | --- | --- |

## 1.7 深交所和上交所的关键区别

| 问题 | 深交所 | 上交所 |
| --- | --- | --- |
| 撤单在哪 | `trades.csv`，`event=CANCEL`，一边订单号为 0，价格为 0 | `orders.csv`，`event=CANCEL`，自带价格和方向 |
| 委托和成交怎么排序 | 按 `seq`，两边共用一套序号，**严格有序** | 没有共用序号，只能按 `time`；同一毫秒的先后要靠订单号自己定 |
| 委托数量 | 原始委托量 | 股票、ETF 是**剩余量**：先成交，剩下的才写 ADD |
| 幽灵订单 | 没有，每个订单都有 ADD | 一进门就全部成交的订单，**不会出现在 orders.csv** |
| 委托类型 | 有 | 没有（ADD 都带真实挂单价） |
| 主动方向 | 万得给了；AX 不给 | 给了 |

已在数据上验证过的事实：

- 深市：`seq` 不重复；按 `seq` 排序后时间不倒退；撤单 100% 是“一边订单号为 0、价格为 0”（000001、300750 都成立）。
- 深市：市价单的价格字段不可信，例如 000001 的 929 笔市价单里有 5 笔带正价格；本方最优单的价格字段和本方一档一次都没对上。
- 沪市：每一笔 CANCEL 都能找到更早的 ADD；被动方 100% 能在 ADD 里找到；ADD 的订单号随文件顺序从不倒退、不重复。
- 沪市幽灵订单：603353 有 20,812 笔，518880 有 164,916 笔，**110093（可转债）是 0 笔**。
- 沪市 STATUS 行：603353 在 9:14 `I`、9:25 `O`、14:57 `J`、15:00 `C`。**推测**是交易阶段切换，说明书没写，使用前要确认。

# 第二部分：合并成逐笔流以后长什么样

## 2.1 为什么要合并

订单簿是沿着**一条时间线**变化的，可委托和成交在两个文件里。所以第一步要把两个文件拼成一张表，排好先后，后面从头读到尾就行。

不能直接 `pd.concat`：两个文件的列不一样，直接拼会补出 NaN，整数订单号变成小数，还混进用不到的列。所以先把委托、成交**各自整理成同样的十列**，再拼，再排序。

## 2.2 十列（深沪整理后完全一样）

定义在 `build_orderbook.py` 的 `TICK_BY_TICK_COLUMNS`：

| 列 | 含义 | 谁有 |
| --- | --- | --- |
| seq | 先后顺序。深市：交易所序号；沪市：排序后自己从 1 编 | 都有 |
| time | 时间 hhmmssmmm | 都有 |
| event | `ADD` 新委托 / `TRADE` 成交 / `CANCEL` 撤单 | 都有 |
| side | `B` / `S` | ADD、CANCEL 有；TRADE 留空 |
| order_type | `LIMIT` / `MARKET` / `BEST_OWN` | 只有 ADD（沪市统一 `LIMIT`） |
| price / qty | 价格（0.0001 元）/ 数量 | 都有 |
| order_no | 新委托**自己**的订单号 | 只有 ADD |
| buy_no / sell_no | 成交或撤单涉及的买方、卖方订单号 | TRADE、CANCEL。撤单时被撤的一边写订单号，另一边是 0 |

没有的值用 `Int64`（大写 I，能放空值的整数类型）的空值 `<NA>`。

## 2.3 深市：按 seq 一排就好

手造测试数据 `sz_tiny` 拼完的样子：

```
seq  time      event   side  order_type  price   qty  order_no  buy_no  sell_no
1    93000000  ADD     S     LIMIT       108500  300  1
2    93000010  ADD     B     LIMIT       108400  200  2
3    93000020  ADD     B     MARKET      0       100  3
4    93000020  TRADE                     108500  100            3       1
5    93000030  CANCEL  B                 0       200            2       0
```

撤单的 `side` 是推出来的：哪边订单号不为 0，就撤哪边。000001 拼完 151,713 行（ADD 81,113 / TRADE 45,405 / CANCEL 25,195），seq 不重复，时间不倒退。

## 2.4 沪市：自己造顺序

**整理时做三件事：**

1. STATUS 行丢掉；
2. ADD 的 `order_type` 填 `LIMIT`（沪市 ADD 都带真实挂单价）；
3. CANCEL 装扮成深市撤单的样子：`order_no` 挪进 `buy_no`（撤买单）或 `sell_no`（撤卖单），另一边填 0，`order_no` 留空。

**排序：按（time, key, rank）逐级比较，再编 seq。**

| 辅助列 | 规则 | 为什么 |
| --- | --- | --- |
| key | ADD → 自己的订单号；TRADE → 较大的订单号；CANCEL → 被撤订单号 | 订单号按到达顺序递增，能当先后用；成交里号大的是后到的主动方 |
| rank | key 相同时：股票 / ETF 成交 0、ADD 1、撤单 2；可转债 ADD 0、成交 1、撤单 2 | 股票、ETF 先成交、剩余量才写 ADD；可转债 ADD 是完整量；撤单一定在这张订单的其他事之后 |

参数 `trade_before_add`：股票、ETF 用默认的 `True`；可转债必须传 `False`。

**例子：603353，9:30:03.400 这一毫秒，排好之后：**

```
seq   event   side  price   qty   order_no  buy_no  sell_no   key     rank
7978  CANCEL  B     422300  100             134805  0         134805  2
7979  CANCEL  S     463400  11400           0       489777    489777  2
7980  TRADE         463300  300             672227  672843    672843  0
7981  TRADE         463300  200             672227  672903    672903  0   ← 672903 主动卖
7982  TRADE         463300  200             672645  672903    672903  0
7983  ADD     S     462600  2600  672903                      672903  1   ← 剩余量挂上卖盘
7984  TRADE         462600  800             673016  672903    673016  0   ← 后来的买单吃它
7985  TRADE         462600  100             673324  672903    673324  0
7986  ADD     S     463100  100   673599                      673599  1
```

（`key`、`rank` 只在排序时用，最终的逐笔流里没有这两列。）如果只按 `time` 排，委托的行都会排在成交前面，672903 的 ADD 就跑到它自己的成交前面了，回放时剩余量会被扣成负数。

> **注意**：排序规则是从三份沪市样本里归纳的，收盘对账都通过了，但还没有逐张快照验证，也没有交易所文档确认。

# 第三部分：订单簿长什么样

## 3.1 三本字典

订单簿在 `build_orderbook.py` 的 `OrderBook` 类里，就是三本字典。用“记账员”的话说：两块**黑板**给大家看，一个**本子**自己翻查。

```
bids    价格 -> 该价位买单总量          黑板（买盘）
asks    价格 -> 该价位卖单总量          黑板（卖盘）
orders  订单号 -> [方向, 价格, 剩余量]  本子
```

例：`sz_tiny` 回放完的状态

```
orders = {1: ["S", 108500, 200]}
asks   = {108500: 200}
bids   = {}
```

为什么要有本子：成交和撤单的记录只给订单号，不给这张订单当初的挂单价（成交行写的是成交价，深市撤单的价格是 0）。挂单价只在它自己的 ADD 行出现过一次，所以要记下来，后面才知道去黑板的哪一行扣。

黑板上不记订单号：交易所的快照本来就只有每档的总量；我们不撮合，谁和谁成交已经写在成交记录里，不需要知道每个价位的排队顺序。

## 3.2 每种行怎么改订单簿

| 逐笔流的行 | 本子 orders | 黑板 bids / asks |
| --- | --- | --- |
| ADD LIMIT | 记 [方向, 委托价, 数量] | 委托价那一行加数量 |
| ADD BEST_OWN（深市） | 记 [方向, 本方一档价, 数量] | 本方一档那一行加数量 |
| ADD MARKET（深市） | 记 [方向, None, 数量] | 不上黑板，等后面的成交、撤单结清 |
| TRADE | 买方、卖方各扣成交量，扣完删掉 | 有价格的那一方，在它的价位扣掉 |
| CANCEL | 被撤订单扣撤单量，扣完删掉 | 在它的价位扣掉 |

扣的时候找不到订单号、或者剩余量扣成负数，不报错，记在 `problems` 计数器里，继续往下读。

## 3.3 查询和对账

- `best_bid()` / `best_ask()`：买一 / 卖一价，没有挂单时返回 `None`。
- `top_levels(n)`：买卖各前 n 档，`[(价格, 数量), ...]`，买盘从高到低，卖盘从低到高。
- `build_order_book(tick_by_tick, stop_time)`：回放到 `stop_time` 停下，得到那一刻的订单簿。
- `compare_with_snapshot(book, snapshot)`：前十档和一张快照逐档比，返回 10 行的对账表。
