深交所订单簿重建教程

代码：lob_rebuild/src/lob/sz_stock_build_orderbook.py（深市拼逐笔流）+ build_orderbook.py（公共：建订单簿、对账） · 数据：SZ_000001_20260302、SZ_300750_20220426

1、我们要做什么

先说清楚目标。交易所每隔几秒会发一张“十档快照”，告诉你买一到买十、卖一到卖十各有多少股。可是两张快照之间，盘口到底怎么变的，快照不告诉你。

L2 逐笔数据把每一笔委托、每一笔成交、每一笔撤单都记下来了。说白了，我们要做的事就是：拿着这些逐笔记录，从开盘第一笔开始，一笔一笔地把盘口“演”出来。演到哪一刻停下来，手上就是那一刻的盘口。

怎么知道演对了？收盘时，拿我们演出来的十档，和交易所最后一张快照一档一档比。价格和数量全部相同，就说明这一天每一步都没出错。

核心要点：输入是一只股票一天的逐笔数据，输出是重建出的订单簿和对账表。我们只做“回放”，不做“撮合”：谁和谁成交，交易所已经写在成交记录里了，我们照着加减就行。

整个流程只有三步，就是 main() 里写的那样：

1.1 整体思路：先拼逐笔流，再建订单簿

整个项目就两步，代码也按这两步分了文件：

步骤做什么代码在哪
第 1 步：拼逐笔流把委托、成交两个文件整理成同一张十列的表，排好先后各交易所各写各的：sz_stock_build_orderbook.py（深市）、sh_stock_build_orderbook.py（沪市）
第 2 步：建订单簿沿逐笔流一行一行回放，改订单簿；最后和快照对账公共文件 build_orderbook.py，深沪共用

你可能会问：为什么这样分？因为两个交易所的原始数据长得不一样（撤单写在哪、有没有排队号），但只要第 1 步把它们都整理成同样的十列，第 2 步就完全一样了。所以“不一样的”放在各自的文件里，“一样的”只写一份。

小技巧：本篇第 2、3 章讲深市怎么拼逐笔流（深市文件），第 4 到 10 章讲订单簿（公共文件）。沪市篇只需要重讲“拼逐笔流”那部分，订单簿直接沿用本篇。

一句话：用逐笔记录把盘口一笔一笔演出来，收盘时和交易所快照对一对；先拼逐笔流（分交易所），再建订单簿（公用）。

2、深市数据长什么样

深市给我们两个文件。先看几行，心里有个样子：

orders.csv（逐笔委托）
seq   time       side  order_type  price   qty   order_no
1     93000000   S     LIMIT       108500  300   1
2     93000010   B     LIMIT       108400  200   2
3     93000020   B     MARKET      0       100   3

trades.csv（逐笔成交，撤单也在这里）
seq   time       event   bs_flag  price   qty   buy_no  sell_no
4     93000020   TRADE   B        108500  100   3       1
5     93000030   CANCEL           0       200   2       0

这就是测试用的手造数据 sz_tiny。有三件事要注意：

  • 撤单在成交文件里。撤单那一行，被撤的那一边写订单号，另一边是 0，价格也是 0。
  • 两个文件共用一套 seq。seq 是交易所发的“排队小票”，不管是委托还是成交，都按先后往下发。所以两个文件合起来按 seq 一排，就是一天里所有事件的真实先后。
  • 成交和撤单行里没有“订单当初挂在哪个价格”。成交行的价格是成交价，撤单行的价格是 0。订单的挂单价只在它自己的委托行里出现过一次。这一点第 5 章会用到。

小技巧：成交行里的 bs_flag 是主动方向（B 主动买、S 主动卖），主动方就是订单号较大、后到的那一方。它对做因子有用，对重建盘口不是必须的。

一句话：深市两个文件共用 seq，撤单藏在成交文件里，而订单的挂单价只出现在委托行。

3、合成一条逐笔流

代码：sz_stock_build_orderbook.py 的 load_sz_tick_by_tick

订单簿是沿着一条时间线变化的，所以第一步要把两个文件合成一张表，按 seq 排好，后面从头读到尾就行。

你可能会问：直接 pd.concat 两个文件再排序，不就完了？嗯，这里有个坑。

避坑指南：两个文件的列不一样。直接拼，pandas 会把对方没有的列补成 NaN。整数一旦遇到 NaN，就会被悄悄变成小数，订单号 1009 变成 1009.0；另外一些用不到的列（raw_type、src_row 等）也混进来。

所以中间加了一层：先把委托、成交各自整理成同样的十列，再拼。这十列定义在 TICK_BY_TICK_COLUMNS 里：

列含义谁有
seq / time先后顺序 / 时间 hhmmssmmm都有
eventADD 新委托 / TRADE 成交 / CANCEL 撤单都有
sideB / SADD、CANCEL 有；TRADE 留空
order_typeLIMIT / MARKET / BEST_OWN只有 ADD
price / qty价格（0.0001 元）/ 数量（股）都有
order_no委托自己的订单号只有 ADD
buy_no / sell_no成交或撤单涉及的买方、卖方订单号TRADE、CANCEL

没有的值用 Int64（大写 I）的空值占位，这种整数类型可以放空值，不会变成小数：

part["order_no"] = orders["order_no"].astype("Int64")
part["buy_no"] = pd.array([pd.NA] * len(orders), dtype="Int64")   # 新委托没有关联订单号，留空

撤单的方向顺手补上：哪边订单号不是 0，就是撤哪一边。这只是为了后面写起来方便，不是必须的。

is_cancel = part["event"] == "CANCEL"
part.loc[is_cancel & (part["buy_no"] != 0), "side"] = "B"
part.loc[is_cancel & (part["sell_no"] != 0), "side"] = "S"

最后拼起来，按 seq 排：

tick_by_tick = pd.concat([order_part, trade_part], ignore_index=True)
tick_by_tick = tick_by_tick.sort_values("seq", ignore_index=True)
return tick_by_tick[TICK_BY_TICK_COLUMNS]

000001 这一天合出来 151,713 行：ADD 81,113、TRADE 45,405、CANCEL 25,195；seq 不重复，按 seq 排好后时间一次都没倒退。

一句话：先各自整理成同样的十列再拼，才不会让订单号变成小数、混进无用的列。

4、回放：一行一行读

从这一章到第 10 章，代码都在公共文件 build_orderbook.py 里，深沪共用。

表排好了，接下来就是从第一行读到最后一行，每一行交给订单簿处理：

def build_order_book(tick_by_tick: pd.DataFrame, stop_time: int | None = None) -> OrderBook:
    order_book = OrderBook()
    for row in tick_by_tick.itertuples(index=False):
        if stop_time is not None and row.time > stop_time:   # 超了就停
            break
        order_book.apply_row(row)                            # 走到这里，说明没超
    return order_book

4.1 为什么用 itertuples(index=False)？

你可能会想，直接 for row in tick_by_tick 不行吗？不行，直接遍历 DataFrame 拿到的是列名，不是行。

itertuples 一次给你一行，而且是带名字的元组，可以用 row.event、row.qty 取值，又快又清楚。index=False 的意思是：不要把行号塞进来当第一个字段，我们用不到它。

小技巧：iterrows 也能按行读，但慢很多，而且会把一行的类型统一，整数可能变成小数。十几万行的回放，用 itertuples。

4.2 为什么要有 stop_time？

想看 10:00 那一刻的盘口？传 stop_time=100000000，读到超过这个时间的第一行就停下，手上的订单簿就是那一刻的。以后做“每张快照都对账”、画某个时刻的深度图、算因子，都靠它。

避坑指南：判断要写在 apply_row 之前。写在后面，就会先把超时的那一行处理掉，再停，多处理了一行。

一句话：itertuples 一行一行喂给订单簿，stop_time 让你停在任意时刻。

5、黑板和本子：三本字典

这一章是整个项目的核心，我们用一个小故事讲。

你是菜市场的记账员，墙上有一块黑板，写着每个价位还有多少人想买、多少人想卖：

卖:  108600 → 300股
     108500 → 500股      ← 卖一
买:  108400 → 200股      ← 买一
     108300 → 700股

大家只看这块黑板，这就是订单簿。在代码里，它是两本字典：

self.bids = {}       # 价格 -> 买单总量
self.asks = {}       # 价格 -> 卖单总量

为什么分成两本？买盘要找最高价，卖盘要找最低价，分开后 best_bid() 只看 bids 取最大，best_ask() 只看 asks 取最小，互不干扰。

5.1 黑板够用吗？来一张撤单纸条试试

逐笔流里来了一行：CANCEL，订单 10，撤 200 股。你要在黑板上划掉 200 股，可是该划哪一行？

纸条上只有订单号和股数，价格是 0。黑板上只写着“108400 共 200 股”，不写这 200 股是谁的。你在黑板上找不到订单 10。成交纸条也一样，它写的是成交价，不是订单 10 当初挂的价。

5.2 所以要有一个本子：orders

订单 10 刚来的时候，你一边写黑板，一边在本子上记一笔：

self.orders = {}     # 订单号 -> [方向, 价格, 剩余量]
# 订单10 到达时：
orders[10] = ["B", 108400, 200]

以后来了撤单或成交纸条，先翻本子，查到订单 10 挂在 108400，再回黑板把 108400 那一行减掉，最后把本子上的剩余量也减掉。剩余量减到 0，这一笔就从本子上划掉。

字典回答的问题给谁看
bids买盘每个价位一共多少股？大家看（订单簿本身）
asks卖盘每个价位一共多少股？
orders某个订单号挂在哪、还剩多少？只给自己翻查（账本）

5.3 黑板上为什么不写订单号？

两个原因。第一，交易所公布的快照本来就只有每档的价格和总量，我们的目标是重建出一样的东西。第二，我们不撮合。撮合引擎要知道同一价位谁排在前面，所以每个价位下要挂一个排队的订单队列；我们不需要，因为成交记录已经写明了是哪两个订单成交的，照着减就行。

小技巧：以后想做“我的单子前面还排着多少股”这类因子，再把 bids[price] 从一个数字改成按时间排好的订单队列。现在不用。

一句话：黑板（bids/asks）记每个价位的总量，本子（orders）记每个订单挂在哪；成交和撤单纸条不写挂单价，只能靠本子查。

6、apply_row：分派纸条

每一行逐笔就是一张纸条，只有三种。apply_row 看一眼是哪种，交给对应的人去办：

def apply_row(self, row) -> None:
    if row.event == 'ADD':
        self.add_order(row.order_no, row.side, row.order_type, row.price, row.qty)
    elif row.event == 'TRADE':
        self.apply_trade(row.buy_no, row.sell_no, row.qty)
    elif row.event == 'CANCEL':
        order_no = row.buy_no if row.side == 'B' else row.sell_no
        self.apply_cancel(order_no, row.qty)
    else:
        raise ValueError(f"未知的 event: {row.event}")

它是“逐笔流”和“订单簿”之间的接口。以后逐笔流的列名变了，只改这里，订单簿里面一行都不用动。

注意最后的 raise：碰到不认识的事件，说明数据整理那一层出错了，继续跑没有意义，所以直接停下。这和第 8 章的 return 是两种不同的处理，我们到那里再对比。

一句话：apply_row 只负责看纸条类型、分派，具体加减交给下面的方法。

7、add_order：三种委托怎么挂

新委托来了，要做三件事：算出挂在哪个价格 → 记进本子 → 写上黑板。难点在第一件，因为深市有三种委托：

类型挂在哪为什么
LIMIT 限价自己的委托价—
BEST_OWN 本方最优到达那一刻本方的最优价（买单取买一，卖单取卖一）它的价格字段不可信
MARKET 市价不上黑板，价格记 None它没有挂单价，进来就吃对手盘

避坑指南：本方最优单的价格字段在 000001（159 笔）和 300750（7 笔）里，和本方一档一次都没对上，常见的是 0、涨停价这类无意义的值。所以不能用它，要自己去黑板上查本方一档。

def add_order(self, order_no, side, order_type, price, qty) -> None:
    # 1. 算出挂单价格
    if order_type == "LIMIT":
        price = price                      # 就用传进来的委托价
    elif order_type == "BEST_OWN":
        if side == "B":
            price = self.best_bid()
        else:
            price = self.best_ask()
        if price is None:                  # 本方一个挂单都没有，算不出价格
            self.problems["本方最优单到达时本方没有挂单"] += 1
    elif order_type == "MARKET":
        price = None

    # 2. 记进本子（三项：方向、价格、剩余量）
    self.orders[order_no] = [side, price, qty]
    # 3. 有价格才写上黑板
    if price is not None:
        self._add_to_level(side, price, qty)

7.1 市价单不上黑板，那它的股数去哪了？

用记账员的话说：市价单进门，你在本子上记“订单 3，买，价格空，100 股”，黑板上一笔都不写。紧接着交易所会发来成交纸条“订单 3 和订单 1 成交 100 股”，你翻本子把订单 3 扣到 0、划掉；订单 1 在黑板上的那一行也扣掉 100。

所以市价单的股数不用担心，后面的成交（没成交完的部分会被撤单）会把它结清。000001 这一天回放完，本子里价格为空的订单一笔都没剩。

7.2 _add_to_level：在黑板某一行上加减

def _add_to_level(self, side, price, qty) -> None:
    """qty 可以是负数，表示减；减到 0 就把这个价位删掉。"""
    if side == "B":
        order_side = self.bids
    else:
        order_side = self.asks

    if price in order_side:
        order_side[price] += qty
    else:
        order_side[price] = qty

    if order_side[price] <= 0:
        del order_side[price]

加和减用同一个函数，减的时候传负数。减到 0 要把这个价位删掉，不然黑板上会留一堆“0 股”的空行，买一卖一就找错了。

一句话：限价挂委托价，本方最优挂本方一档，市价只记本子不上黑板，等后面的成交来结清。

8、_reduce_order：成交和撤单

成交纸条涉及两个订单，各扣一次；撤单纸条涉及一个订单，扣一次。所以这两个方法几乎没有内容，真正干活的是 _reduce_order，也就是“翻本子扣账”这个动作：

def apply_trade(self, buy_no, sell_no, qty) -> None:
    self._reduce_order(buy_no, qty)
    self._reduce_order(sell_no, qty)

def apply_cancel(self, order_no, qty) -> None:
    self._reduce_order(order_no, qty)
def _reduce_order(self, order_no, qty) -> None:
    # 1. 翻本子，找不到就记一笔、跳过
    if order_no not in self.orders:
        self.problems["找不到订单号"] += 1
        return

    # 2. 剩余量减掉
    side, price, remaining_qty = self.orders[order_no]
    remaining_qty -= qty
    if remaining_qty < 0:
        self.problems["剩余量变负"] += 1

    # 3. 挂在黑板上的，黑板那一行也减掉
    if price is not None:
        self._add_to_level(side, price, -qty)

    # 4. 扣完了就从本子上划掉，否则写回新的剩余量
    if remaining_qty <= 0:
        del self.orders[order_no]
    else:
        self.orders[order_no][2] = remaining_qty

8.1 找不到订单号时，为什么是 return 而不是 raise？

记账员收到“撤订单 10”，翻遍本子没找到。他有三种做法：

  1. 什么都不做，往下写。下一行 self.orders[order_no] 会直接报 KeyError。所以必须离开这个函数。
  2. raise，整个程序停掉。后面还有十几万张纸条，一张有问题就让全天中断，你连还有多少问题都看不到。
  3. return，记一笔，跳过这一张。全天跑完后看 problems，就知道问题有多少。

还有一个细节：apply_trade 调了两次 _reduce_order。买方那次 return，只是结束买方这一次调用，卖方那次照样执行，该扣的还是扣了。如果用 raise，卖方就没机会扣，盘口会一路错下去。

核心要点：能计数的问题就计数后跳过（return）；只有继续跑已经没意义时才 raise，比如 apply_row 碰到不认识的事件。在深市，“找不到订单号”和“剩余量变负”都应该是 0，不是 0 就说明代码写错了。

8.2 用 sz_tiny 走一遍

seq1 ADD 卖1 LIMIT 108500×300  → orders={1:[S,108500,300]}             asks={108500:300}
seq2 ADD 买2 LIMIT 108400×200  → orders 加 2:[B,108400,200]            bids={108400:200}
seq3 ADD 买3 MARKET ×100       → orders 加 3:[B,None,100]              黑板不变
seq4 TRADE 买3 卖1 ×100        → 订单3 扣到0删掉；订单1 剩200          asks={108500:200}
seq5 CANCEL 买2 ×200           → 订单2 扣到0删掉                       bids={}

结果：orders={1:[S,108500,200]}  asks={108500:200}  bids={}

这正是测试 test_回放手造数据 断言的结果。

一句话：成交和撤单都是“翻本子 → 扣黑板 → 扣本子”，找不到就记一笔跳过，不让一张坏纸条毁掉整天。

9、查询：买一卖一和前十档

买一卖一很简单，只有一个坑：刚开盘时黑板是空的，对空字典调用 max() 会报错。所以先判断空不空：

def best_bid(self) -> int | None:
    if self.bids:
        return max(self.bids.keys())
    else:
        return None

def best_ask(self) -> int | None:
    if self.asks:
        return min(self.asks.keys())
    else:
        return None

注意 add_order 处理本方最优单时要调用它们，所以它们得先写好。

前十档就是排个序、取前 n 个。.items() 把字典拆成一对一对的 (价格, 数量)；sorted 对这样的元组默认按第一个元素（价格）从小到大排，买盘要从高到低，加 reverse=True：

def top_levels(self, n: int = 10) -> tuple[list, list]:
    bids = sorted(self.bids.items(), reverse=True)[:n]   # 价格从高到低
    asks = sorted(self.asks.items())[:n]                 # 价格从低到高
    return bids, asks                                    # 逗号造元组，等于 return (bids, asks)

小技巧：现在 max / min / sorted 每次都要把整个字典扫一遍。以后要提速（缓存、有序结构、按价位下标的数组），只改这几个查询方法，其他代码不用动。

一句话：买一取 bids 最大、卖一取 asks 最小，空的时候返回 None；前十档就是排序后切片。

10、对账和验收

11、回头看和下一步

回头看，整个深市重建其实就是一句话：按 seq 读纸条，ADD 写本子和黑板，TRADE 和 CANCEL 翻本子再扣黑板。能这么简单，靠的是深交所数据的两个好性质：

  • 委托和成交共用 seq，顺序是交易所给好的，不用猜；
  • 每个订单都有一行 ADD，哪怕它一进门就全部成交，所以本子里一定查得到。

到了上交所，这两条都不成立：没有共用的 seq，一进门就吃完的订单也没有 ADD。但订单簿本身（OrderBook）、回放（build_order_book）和对账（compare_with_snapshot）都在公共文件 build_orderbook.py 里，与交易所无关。沪市文件 sh_stock_build_orderbook.py 只需要把沪市数据拼成同样的十列逐笔流，再调用公共函数。这部分在 SH 教程里讲。

后续做什么
逐张快照对账每张快照都用 stop_time 停下来比一次，不只比收盘
深市规则集合竞价、创业板价格笼子等，对着交易所规则原文核实
上交所没有 seq 时怎么排序、幽灵订单怎么处理
批量和因子多只股票批量跑，从订单簿算特征
一句话：深市能“照着纸条加减”就重建出盘口，是因为顺序和订单都齐全；沪市缺了这两样，要补的只是读数据那一层。
